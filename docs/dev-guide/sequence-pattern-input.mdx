`SequencePatternInput` is the canonical control for `format:"sequence_pattern"`
columns — the **authoring** surface for sequence patterns (the sequence
entity's `pattern` column uses it). It is distinct from `format:"sequence"`,
which binds a seq-claim directive: here the bound value is the **authored
pattern string**, persisted verbatim.

```ts
import { SequencePatternInput } from "@primebrick/ui";
```

## Canonical value contract

The bound value is the literal pattern text — grammar:

- exactly one counter slot: `{seq}` or `{seq:W}` (`W` 1–19)
- date tokens, at most once each: `{yyyy}` `{yy}` `{MM}` `{dd}` `{q}`
- time tokens, at most once each — cosmetic claim-time stamps, never
  period-scoped: `{HH}` (24h) `{hh}` (12h) `{mm}` (minutes) `{ss}` (seconds).
  **Case IS the grammar**: `{MM}` is month, `{mm}` is minutes.
- partition tokens, at most once each: `{sez}` `{sez2}` `{sez3}`
- literal braces escaped as `{{` / `}}`; arbitrary literal text otherwise

Validation rides the shared `checkFieldValue` path (`format` case →
`parseSequencePattern`) — the same predicate the wire validator runs, so an
invalid pattern is blocked client-side with the standard field chrome.

## Anatomy

```
[ pattern text                              🏷 tags-cta] [⌫ eraser]
✓ Preview: INV-2026-0001          ← interpreter strip (scheduler-style)
```

- **Interpreter strip** — directly under the input, the
  `schedule-spec-input` convention (`flex items-start gap-1.5 px-1
  text-xs`, no enclosing box): `CircleCheck` + `Preview: <rendered>` while
  the pattern parses, `CircleAlert` + the parser error while it doesn't.
  Hidden entirely on empty input. The example renders through the shared
  `renderSequenceValue` — counter rides `context.start` when the host
  record carries it (else `sequenceTokenExampleDefaults.counter`),
  partitions ride the shared catalog defaults.

- **Free typing** — arbitrary literal text is always accepted verbatim.
- **Anatomy** — a plain `Input` inside a `relative` wrapper; the trailing
  controls are the standard floating icon chips
  (`inputTrailingIconButtonClasses` → `inputTrailingIconColorClasses`), the
  same treatment `Input`'s own clear/copy/search slots use — **not**
  `InputGroup`/`InputGroupButton` blocks (those are reserved for
  `NumericInput` steppers and UOM adornments).
- **Tags CTA** — lucide `Tags` icon, second trailing slot (`right-10`), left
  of the eraser; fires the host-injected `on_pick` (same contract family as
  `NumericInput`'s `uom.on_pick`). ui stays environment-neutral: the host
  wires `openSheet('entity.sequencePattern', …)`.
- **Eraser** — rightmost floating chip (`right-1.5`), the standard clear
  icon; disabled on empty. With both CTAs the input carries `pr-14` so text
  never slides under the icons.

## Host contract (`on_pick`)

```ts
interface SequencePatternPick {
  get_value: () => string;                          // live pattern getter
  get_caret: () => { start: number; end: number } | null;  // tracked selection — null = untouched → append
  context?: Record<string, unknown>;                // the form record (step/start/tz previews)
}
```

`get_caret` reads the widget's tracked selection — but note it freezes the
moment the stack remount kills the widget instance. The host's token
surface should therefore prefer, in order: the input's **live DOM
selection** (Chrome preserves it across blur), then a **host-side live
caret** recorded from real selection events on the element (the FE
dispatcher keeps one for the sheet's lifetime), then `get_caret()` — the
open-time value. `null` all the way = untouched → append.

## Token surface (host side)

The FE mounts `entity.sequencePattern` as a **stacked sheet** (record pane
stays on the left). It renders `sequenceTokenCatalog()` from
`@primebrick/core` — grammar knowledge is never duplicated — with per-token
syntax, localized label, a rendered example, and an insert CTA.

- **One counter row** — `kind:"counter"` is listed once; its padding is
  authored in the small form right under the row (`0` = no padding, the
  default; `N` → `{seq:N}` on insert). While the slot is consumed the form
  mirrors the pattern's `counter_width`, disabled.
- **Used slots** carry the lucide `Tags` badge plus a `-` remove CTA —
  `removeSequenceToken(source, slot)` strips the whole token span
  (`{seq:W}` included, escapes untouched) and the host writes the result
  through the same live channel (`on_write`).
- **i18n keys are explicit** — `spec.key`, not `id.toLowerCase()`: `{MM}`
  (month) and `{mm}` (minutes) would collide as `mm`, so minutes is `min`
  and `{HH}`/`{hh}` are `hh`/`hh12`.
- A live preview interpolates the pattern through the shared
  `renderSequenceValue` — display-only (no sample-value inputs; the
  counter comes from the host record's `start` or
  `sequenceTokenExampleDefaults`, partitions from the same defaults).
  Invalid patterns show the parser error, never a guess. Neither the
  token list nor the preview sit inside a bordered card — flat rows
  under the section titles.

Because stacking **remounts** the record pane, the host writes tokens
through the **live DOM input** (`el.value` + `input` event — the real bind
chain, identical to keystrokes) rather than component bindings captured in
the pick — those orphan the moment the pane remounts. For the same reason
the widget's clear CTA writes through the DOM channel too, so the sheet's
`on_change` feed sees the erase exactly like keyboard deletion.

| Record sheet | same dispatcher — the token sheet stacks over it |

## Common pitfalls

- **Never reuse `format:"sequence"`** — that is the seq-bound directive
  contract; pattern authoring is a separate semantic and needs its own
  format.
- **`get_caret()` freezes post-remount** — the live DOM selection is
  authoritative when present; only `{0,0}` consults the tracked fallbacks.
- **Token labels are `snake_case` keys via `spec.key`** — the i18n
  vocabulary is `app.widgets.sequence_pattern.tokens.<key>`; the key is
  explicit because case-meaningful ids would collide under lowercasing
  (`MM`/`mm` → `mm`/`min`, `HH`/`hh` → `hh`/`hh12`).
